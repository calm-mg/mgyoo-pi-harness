# 변경 리뷰

1. 요청에 명시된 커밋·브랜치·파일 범위를 확인한다. 범위가 없다면 현재 작업 트리의 staged/unstaged diff와 새 파일 목록을 확인한다. 파일을 수정하거나 사용자 변경을 되돌리지 않는다.
2. 변경 전후 동작을 비교한다. 호출부, 오류 경로, 경계값과 관련 테스트를 읽고 실제로 어떤 입력에서 어떤 결과가 달라지는지 확인한다.
3. 검증할 수 있는 문제만 영향도 순으로 정리한다. 각 항목에 파일과 줄, 문제가 발생하는 조건, 예상 결과와 실제 결과를 적는다. 스타일 취향은 결함과 구분한다.
4. 문제가 없다면 검토한 범위와 발견 사항이 없음을 말한다. 실행한 검증과 실행하지 못한 검증, 남은 불확실성을 구분한다.
