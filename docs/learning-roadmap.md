# Pi 학습 로드맵

문서 기준일: 2026-07-24  
공식 문서: https://pi.dev/docs/latest

## 첫째 날: 안전하게 시작

- 설치하고 `pi-doctor`를 통과한다.
- `pi-login safe`로 한 provider를 연결한다.
- `/model`로 모델을 선택한다.
- 읽기 전용 프로젝트 설명을 요청한다.

완료 기준: SAFE와 YOLO의 권한 차이를 말로 설명할 수 있다.

## 둘째 날: session과 steering

- 작은 문서 수정 작업을 한다.
- 작업 도중 추가 지시를 보낸다.
- session을 새로 만들고 이전 session을 다시 찾는다.

완료 기준: 서로 다른 작업을 한 session에 무리하게 섞지 않는다.

## 셋째 날: 모델과 thinking

- 같은 작은 문제를 서로 다른 모델로 시도한다.
- thinking level을 낮음/높음으로 바꿔 차이를 기록한다.
- 비용, 속도, 결과 품질을 비교한다.

완료 기준: 무조건 가장 큰 모델을 쓰지 않고 작업에 맞게 선택한다.

## 넷째 날: 프로젝트 지침

- 프로젝트 `AGENTS.md`에 실제 규칙 3개를 적는다.
- 모호한 규칙을 검증 가능한 문장으로 바꾼다.
- 규칙이 기존 사용자 변경을 보존하도록 한다.

완료 기준: Pi가 규칙을 따랐는지 diff와 테스트로 판단한다.

## 다섯째 날: 반복 작업 정리

- 세 번 이상 반복한 prompt를 찾는다.
- 입력과 성공 조건을 문서화한다.
- 아직 자동화하지 않고 수동 절차를 다듬는다.

완료 기준: 다른 사람이 절차만 읽고 같은 결과를 낼 수 있다.

## 여섯째 날: skill

- 범위가 작은 개인 skill 하나를 설계한다.
- 실패 시 멈출 조건을 넣는다.
- 비밀정보와 로컬 경로를 제거한다.

완료 기준: 두 프로젝트에서 재사용할 수 있다.

## 일곱째 날: extension 읽기

- `workspace-guard`의 path policy 테스트를 읽는다.
- `tool_call`이 언제 block되는지 추적한다.
- 새 차단 규칙을 테스트부터 추가해 본다.

완료 기준: extension이 sandbox 자체가 아닌 이유를 설명할 수 있다.

## 이후 고도화

1. prompt와 skill 품질 측정
2. 프로젝트 유형별 설정 분리
3. subagent로 조사/구현/검증 역할 분리
4. 반복 작업 자동화
5. 필요할 때만 MCP와 외부 서비스 연결
6. network sandbox 또는 원격 격리 검토

각 단계는 별도 설계, 실패 테스트, 검증 증거를 갖춘 뒤 기본 설정에 포함합니다.
